# Data Model

PostgreSQL 17, schema `scheduler`. Runs on a **single node today**, with a
schema that already obeys the rules a sharded Postgres imposes
([ADR-0008](../adr/0008-tenant-sharding-and-identifiers.md)).

The authoritative definition is the goose migration in
`internal/db/migrations/`. This document explains it.

## Three rules every table obeys

1. **`tenant_id` is the distribution key** and the first column of every table
   except `tenants`.
2. **Every primary key and unique constraint starts with `tenant_id`.**
3. **Foreign keys are composite and tenant-scoped**, so none crosses a tenant.

## Entities

```
tenants 1──* services
        1──* resources ──* availability_rules
        1──* requesters
        1──* bookings ──* booking_events
                  (each booking → one resource, one requester, one service)
```

| Table | Class | Primary key |
|---|---|---|
| `tenants` | reference (replicated when sharded) | `(id)` |
| `services`, `resources`, `requesters`, `availability_rules`, `bookings`, `booking_events` | distributed by `tenant_id` | `(tenant_id, id)` |

Identifiers are `bigint GENERATED BY DEFAULT AS IDENTITY`. They are unique
within a tenant and never meaningful across tenants. `BY DEFAULT` rather than
`ALWAYS` lets the seed loader insert the supplied integers explicitly.

## Constraints and indexes

```sql
-- No double-booking (ADR-0004). Local to one tenant, hence one shard.
EXCLUDE USING gist (
  tenant_id   WITH =,
  resource_id WITH =,
  tstzrange(starts_at, ends_at, '[)') WITH &&
) WHERE (status = 'confirmed');

UNIQUE (tenant_id, idempotency_key) WHERE idempotency_key IS NOT NULL;

INDEX (tenant_id, resource_id,  starts_at) WHERE status = 'confirmed';  -- availability, schedule
INDEX (tenant_id, requester_id, starts_at);                              -- "my appointments"
```

Requires the `btree_gist` extension, created by the migration.

## Seeding from `appointments.json`

The supplied file's integers become the real identifiers, in a default tenant
`1`:

| Seed field | Target |
|---|---|
| `trainer_id` | `resources.id`, one `type = 'trainer'` row per distinct value, timezone `America/Los_Angeles`, with the Mon–Fri 08:00–17:00 rules |
| `user_id` | `requesters.id`, one row per distinct value |
| `id` | `bookings.id` |
| `started_at`, `ended_at` | `starts_at`, `ends_at`, parsed with their offsets and stored as UTC |

Rows are inserted with explicit ids, then each identity sequence is advanced
past the maximum with `setval`, so new rows do not collide. The loader is
idempotent (`ON CONFLICT DO NOTHING`), so a second run changes nothing.

**Known dirty records:** five of the ten seed bookings break current policy. All
of 5, 7, 8, 9 and 10 fall on Saturday 2019-01-26, outside the Monday–Friday
window, and booking 9 also runs 13:00–14:00, sixty minutes where the service is
thirty. They are loaded verbatim and each is reported by the loader rather than
rejected (PRD R-3). A booking still occupies its whole interval for overlap
purposes, so booking 9 blocks both 13:00 and 13:30 on that day.

The seed file lists `ended_at` before `started_at` in each record; field order
carries no meaning and the loader reads by name.
